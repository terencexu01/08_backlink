# 外链发布计划设计文档 — 6 项目（5 工具站 + 1 游戏站）

- **日期**：2026-08-12
- **状态**：待用户审核
- **范围**：基于 backlink-pilot v2.1，为 6 个项目制定可执行的外链发布体系（目录站 + awesome-list + 博客评论），含调度规则、补货机制、协作流程、技术改造点

---

## 1. 背景与目标

用户运营 6 个项目（5 个工具站 + 1 个游戏站）+ 1 个自建 awesome-list（对外接收站，本轮不纳入推广）。希望批量、可持续地发布外链，且**博客评论做到"我（Claude）编写、用户审核"**的高质量模式。

**核心目标**：
1. 每天按固定配额推进三个渠道
2. 目录站、博客评论遵守间隔规则，避免被反垃圾系统判为刷外链
3. 资源边发边补，不依赖"用完再找"
4. 游戏站与工具站做邮箱隔离，降低连坐风险

## 4. 调度规则

### 4.1 目录站（工具站）
- 每个目录站最终会被 5 个工具站各提交 1 次（=5 次）
- **同一目录站，两次提交间隔 ≥ 5 天**
- 每篇目录站对每个工具站只提交一次（查 `submissions.yaml` 去重）
- **示例**（目录站 A）：第 1 天工具① → 第 6 天工具② → 第 11 天工具③ → 第 16 天工具④ → 第 21 天工具⑤

> **"全都要"模式**：用户选择维持 50/天 的同时拉长间隔。按 N=5 设计，工具站目录站库存目标 **300**（现有 180，需新增 120）。若后续想要更长间隔，库存目标相应上调（N=7→420）。

### 4.2 目录站（游戏站）
- 每天提交 3 个游戏类目录站
- 游戏类目录站由 Claude 从 0 建（itch.io 类、HTML5 游戏导航、游戏评测站）
- 同一目录站只提交 1 次（游戏站独占该池）

### 4.3 博客评论（工具站）
- 用**通用主题博客**（开发/效率/设计圈，不细分每个工具站的细分领域，所有工具站都能发）
- **每篇博客最多放 3 个工具站**的评论
- **同一篇博客下，3 个工具站的评论之间间隔 3 天**发（今天工具①，3 天后工具②，再 3 天后工具③）
- 一篇博客 7 天填满 3 站
- 每天约 2 篇新博客、5 条评论
- **示例**（博客 X）：第 1 天工具①评论 → 第 4 天工具②评论 → 第 7 天工具③评论（填满，不再加）

### 4.4 博客评论（游戏站）
- 每天 8-10 条，**每篇博客 1 条**（最安全，避免同篇多邮箱被判刷）
- 用现有 20 条通用模板（`batch-submit.js` 的 `COMMENT_TEMPLATES`）
- 博客池独立（游戏主题），不和工具站混用
- 每天需补 8-10 篇新博客

### 4.5 awesome-list
- 每项目 3 个/周 × 6 = 18 个/周
- 通过 GitHub Issue 提交（`cli.js awesome`）
- 有审核周期，非即时通过

### 4.6 身份隔离
- **仅邮箱隔离**：5 个工具站共用 1 个邮箱；游戏站用专用邮箱（新建）
- 浏览器、IP 共用
- **残余风险**：同 IP 仍可能被反垃圾系统一起画像。监控工具站评论通过率，异常下降则上代理 IP

## 5. 补货机制（边发边补）

**原则**：不等库存用完再找，低于阈值即补，始终保持缓冲。这是用户明确修正的要求——因为间隔提交需要持续的新资源供给，断档会让间隔节奏崩掉。

| 渠道 | 现有 | 目标库存 | 低于即补 | 每次补 |
|---|---|---|---|---|
| 目录站（工具/AI 类） | 180 | 300 | 每项目可用 < 50 | +30 |
| 目录站（游戏类） | ~0 | 60+ | < 20 | +15 |
| 工具站博客 | 0 | 40 | < 15 | +10 |
| 游戏站博客 | 67 | 100+ | < 60 | +30 |
| awesome-list | 26 | 60 | < 20 | +10 |

**补货来源**：
- Claude 联网搜（web-access skill）
- `scout <url> --deep` 验证表单字段
- 开源目录清单（如 naxiaoduo/1000UserGuide）

**质量门槛**（博客）：开放评论、有 website 字段、无 captcha、DoFollow 优先。

**两个现实约束**（必须知晓）：
1. 游戏站目录站几乎从 0 建
2. 目录站总量有天花板：免费、可自动提交的优质目录站全网存量有限，扩到 300 以后新增质量下降（DA 低的小站），需标注质量分级

## 6. 执行架构

**模式：Claude 作为日常执行者 + 现有脚本辅助 + 少量改造。不搞全自动化调度。**

理由：
- 调度规则（间隔 5 天 / 每篇 3 站间隔 3 天 / 每篇 1 条）写死进脚本复杂且脆
- 补货必须联网判断、工具站评论必须 Claude 逐篇读着写，这些本就得 Claude 做
- 自动化只负责"批量提交"（目录站、游戏站博客）；调度 + 评论生成 + 补货由 Claude 每天手动执行

### 6.1 需要的技术改造

| 改造点 | 说明 | 涉及文件 |
|---|---|---|
| `config.yaml` 多项目化 | 从单 `product:` 改为 `projects:` 列表，每项目独立字段 | `src/config.js`、`config.example.multi.yaml` |
| 提交脚本带项目参数 | `cli submit` / `batch-submit` 加 `--project <name>`，按项目取 name+email+utm_url | `src/cli.js`、`src/submit.js`、`src/batch-submit.js` |
| 间隔查询小工具 | 读 `submissions.yaml` + `global-history.json`，自动算出"今天可提交、且不违反间隔规则"的候选清单 | 新增 `src/scheduler.js` |
| 审核文件工作流 | 新建 `reviews/YYYY-MM-DD.md`，Claude 写、用户审 | 新增目录 `reviews/` |
| `batch-submit` 多项目化 | 当前 `PERSONAS` 硬编码、评论来自固定模板。改造点：① 游戏站读专用邮箱（替代硬编码 persona）；② 新增"按审核文件提交"入口——工具站评论内容从 `reviews/` 读取（Claude 手写、用户审过），复用现有表单填充逻辑，不走模板 | `src/batch-submit.js` |

### 6.2 每个项目需要的字段（来自代码审查）

**✅ 必填**（`src/config.js:31` 校验，缺则退出）：`name`、`url`、`description`（<160字符）、`email`
**⭐ 强烈建议**：`long_description`、`categories`、`pricing`、`logo_url`、`github_url`
**可选**：`features`、`twitter`

模板已生成：`config.example.multi.yaml`

## 7. 每日协作流程

| 步骤 | 谁 | 做什么 |
|---|---|---|
| ① | Claude | 查库存 → 跑目录站（工具 50 + 游戏 3，按间隔候选清单选站） |
| ② | Claude | 跑游戏站博客（8-10 条通用模板） |
| ③ | Claude | 跑 awesome-list（当日 ~3 个 GitHub Issue） |
| ④ | Claude | 找 2 篇博客 → 读原文 → 写 5 条工具站评论 → 写进 `reviews/今日.md` |
| ⑤ | 用户 | 看 `reviews/今日.md`，逐条打勾 / 打回 |
| ⑥ | Claude | 提交用户勾过的评论，记录到 `submissions.yaml` |
| ⑦ | Claude | 库存低于阈值（§5）就补货，含游戏类目录站 |

## 8. 审核文件格式

位置：`reviews/YYYY-MM-DD.md`

```markdown
# 工具站博客评论 — 2026-08-12 待审

## ① Metric Converter  →  https://example.com/unit-conversion-guide
评论草稿：
> 这篇里那张"1英寸=2.54cm"的换算表太实用了，省得我老在脑子里算。
> 补充一点：机械加工常用分数英寸(如3/8")，表里加一列分数英寸会更友好。
为什么这么写：引用了文中具体内容(换算表)+补了一个空白(分数英寸)，博主大概率保留。
状态：☐ 待审   [☑ 通过 / ☒ 打回]

## ② PDF Merge  →  https://...
...
```

## 9. 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| 同 IP 连坐（游戏站被标记拖累工具站） | 中 | 仅邮箱隔离；监控工具站评论通过率，异常则上代理 |
| 游戏站通用模板评论被删/拉黑 | 中 | 每篇 1 条、专用邮箱、独立博客池；接受一定损耗 |
| 目录站扩到 300 后质量下降 | 低 | 标注质量分级，提交时可见 |
| 游戏博客资源 1-2 个月后耗尽 | 中 | 8-10/天 已是可持续上限；耗尽前预警，届时降量或扩主题 |
| AI 评论质量不达标 | 低 | 用户每日审核把关；打回则重写 |
